## Overview

Employees file reimbursement claims in the group's HRMS app, where HR approves them. This integration takes approved claims, runs them through approval, pays them through Duluin's existing disbursement pipeline and reports each claim's status back.

## My contribution

- As PIC, designed the integration contract, the claim lifecycle and the approval flow.
- Implemented it across a Go service and the Laravel dashboard.
- Applied the team's security practices: OAuth2 client credentials with scopes, and role-based permissions on every approval step.
- Reused the existing disbursement pipeline instead of building a separate payment path.

## Skills applied

- **Integration design.** A contract and claim lifecycle agreed between two applications owned by different teams.
- **OAuth2.** Client credentials with scopes, later moved to tenant API keys validated by the auth service (see [Auth & API Security](/projects/api-security)).
- **Idempotency.** Each claim carries a unique external ID and is created inside a database transaction, so a retried request can't create a second claim.
- **Concurrency control.** Row-level locks prevent two people from approving the same claim at once.
- **Reuse over rebuild.** Small adapters connect claims to the existing disbursement pipeline, so claims inherit its queues and audit trail.
- **Resilient callbacks.** The status callback retries, and a failed callback is logged without ever rolling back a completed transfer.

## Outcome

- Claims approved in the HRMS app reach employees' bank accounts through an automated, audited flow, with status reported back.
- Partner companies can review claims before they are paid.
